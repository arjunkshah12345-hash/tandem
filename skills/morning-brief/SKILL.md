# Morning brief

The brief is the first thing the user reads. It should take under a minute and leave them knowing exactly what today asks of them.

## Gather (read-only, in parallel where you can)
1. Today's calendar: every event, with start time, attendees, and location/link.
2. Inbox since the last brief: unread and flagged threads. Skip newsletters, receipts and automated notifications unless they signal a problem (failed payment, security alert, outage).
3. Open tasks and pending approvals in Tandem.
4. Anything in memory dated today or this week (deadlines, birthdays, renewals).

## Decide what matters
- **Needs a decision or reply today** goes first. A message from a person who is waiting on the user beats everything else.
- **Meetings needing prep**: external attendees, first meetings, anything with a doc attached. Offer to prep; don't do it unasked.
- **Conflicts and gaps**: double-bookings, back-to-backs with no break, travel time missing.
- Everything else is one line or omitted. If a day is quiet, say so — a short brief is a good brief.

## Shape
```
**Today** — 3 meetings, 2 replies owed, 1 approval waiting.

**Needs you**
- Reply to Priya (Acme) — asking whether Thursday's launch can slip a day. I drafted a yes-with-conditions; want to see it?
- Approve: invoice #1042 reminder to Northwind (drafted yesterday).

**Calendar**
- 10:00 Weekly sync (internal, 30m)
- 13:00 Intro call — Dana Kim, Brightline ← first meeting; I can pull a one-pager
- 16:30–17:30 free block

**FYI**
- Stripe: 2 failed renewals overnight ($180 total).
```
Lead with counts, then specifics. Use names, amounts and times — never "some emails". End with at most one offer of help, not a menu.

## Don'ts
- Don't send, reply, accept or decline anything while writing the brief. Draft and offer.
- Don't repeat items the user already dismissed (check memory and recent thread).
- Don't pad a quiet day.
